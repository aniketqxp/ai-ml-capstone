# Sentiment Analysis Backend Contract

## Purpose

This document explains the output format from Clara's sentiment analysis module so the backend can store the results and connect them with transcription and dashboard data.

The sentiment module takes timestamped transcript segments and audio files, then returns sentence-level sentiment results and call-level summary metrics.

## Important Join Keys

The safest unique key for backend storage is:

call_id + segment_index

The transcript alignment key is:

call_id + seq_id

Why both are included:

- seq_id comes from the transcription JSON and is needed to align with the transcript sentence.
- segment_index is generated by the sentiment export and is guaranteed to be unique inside each call.
- One transcript file currently has a duplicate seq_id, so segment_index and segment_key were added to avoid backend duplicate-key issues.

Recommended backend logic:

- Use call_id + segment_index as the unique database key.
- Keep seq_id for transcript alignment and display.
- Use segment_key as a ready-made unique identifier if needed.

## Field Explanation

Top-level fields:

- call_id: Original AppTek call ID.
- domain: Call domain, such as banking, health, or telecom.
- model_version: Sentiment model version used for inference.
- source_file: The simple sentiment file used to create this backend payload.
- generated_at: Timestamp for when the backend payload was generated.
- join_keys: Explains which keys should be used for backend joins.
- call_summary: Call-level sentiment and risk summary.
- segments: Sentence-level sentiment results.

Call summary fields:

- total_segments: Total transcript sentences returned in the sentiment payload.
- successful_segments: Number of segments successfully analyzed by the audio sentiment model.
- skipped_segments: Number of segments that were too short for reliable audio sentiment prediction.
- dominant_sentiment: Most common sentiment across successful segments.
- dominant_emotion: Most common emotion across successful segments.
- average_escalation_score: Average escalation score across successful segments.
- max_escalation_score: Highest escalation score found in the call.
- risk_level: Call-level risk level based on escalation score.
- processing_status_distribution: Counts of success and skipped segments.
- sentiment_distribution: Counts of sentiment labels across successful segments.
- emotion_distribution: Counts of emotion labels across successful segments.
- duplicate_seq_ids: List of duplicated transcript seq_id values, if any.

Segment fields:

- segment_index: Unique segment order inside the call, starting from 1.
- segment_key: Unique generated key for the segment.
- seq_id: Original sentence sequence ID from the transcription JSON.
- sentiment: Predicted sentiment label.
- dominant_emotion: Predicted dominant emotion.
- escalation_score: Audio escalation score for the segment.
- processing_status: Either success or skipped_too_short.

## Processing Status Values

success:
The segment was long enough and was analyzed by the audio model.

skipped_too_short:
The segment was too short for reliable emotion prediction, so it was kept but not analyzed.

call_id + segment_index

## Backend Integration Steps

1. Read each JSON file from ml-services/outputs/backend/sentiment_calls/.
2. Insert or update the call-level result from call_summary.
3. Insert or update all rows inside segments.
4. Join with the transcript using call_id and segment_index as the safest key.
5. Keep seq_id available for transcript alignment and display.
6. For the dashboard, show both call-level and sentence-level sentiment.
